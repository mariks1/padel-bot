# Padel Americano Bot

TypeScript-проект Telegram-бота и независимого движка генерации турниров Americano.

Контекст для разработки сайта: [модель данных, правила турниров и план общего API](docs/website-integration.md). HTTP API пока не реализован; документ отделяет текущее поведение от предложений по интеграции.

## Запуск

```bash
npm test
npm run build
npm start
```

Для Telegram-бота:

```bash
TELEGRAM_BOT_TOKEN=... npm run bot
```

Бот использует SQLite-файл `data/padel.sqlite`. Путь можно изменить через `PADEL_DATABASE_PATH`.

`npm run bot` также читает настройки из `.env`. Если Telegram доступен только
через HTTP-прокси, задайте `HTTPS_PROXY=http://127.0.0.1:12334` в `.env`,
указав адрес своего прокси. Для поддержки прокси нужен Node.js 22.21+ или 24.5+.

## Docker Compose на Windows

Нужен установленный Docker Desktop в режиме Linux containers.

1. Скопируйте `.env.example` в `.env` и вставьте токен от BotFather:

```powershell
Copy-Item .env.example .env
notepad .env
```

2. Соберите и запустите бота из каталога проекта:

```powershell
docker compose up -d --build
```

3. Посмотрите логи:

```powershell
docker compose logs -f padel-bot
```

Остановка и повторный запуск:

```powershell
docker compose down
docker compose up -d
```

База сохраняется в Docker volume `padel-data` и не удаляется при пересоздании контейнера. Файл `.env` исключён из Docker-образа; его также не следует коммитить.

После `/start` доступны кнопки:

- создание и Telegram-привязка игроков;
- выбор сохранённых игроков в новый турнир;
- выбор кортов и количества очков;
- ввод результатов по раундам;
- личная статистика и общий рейтинг.

В личном профиле и карточке игрока из общего рейтинга показываются два лучших
партнёра: по проценту совместных побед и по средним набранным очкам за совместный
матч. Учитываются все матчи с введённым счётом; рядом отображается размер выборки.
При равенстве показателя предпочтение отдаётся партнёру с большим числом совместных
матчей. В личной статистике и при выборе партнёра винрейт считается как
`(победы + 0,5 × ничьи) / матчи × 100%`: ничья даёт половину победы.
Если сыгранных матчей ещё нет, лучший партнёр не выбирается.

Чужую статистику можно открыть через единственную кнопку «Статистика игрока»
в общем рейтинге, введя имя, часть имени или @username. Быстрый способ:
`/stats Егор` или `/stats @username`. Если совпадений несколько, бот предлагает
выбрать номер текстом, без отдельных кнопок на каждого игрока.

Кнопка «Отменить турнир» доступна в текущем турнире и истории. После подтверждения
турнир остаётся в истории с пометкой «Отменён», а его результаты исключаются из
рейтинга, личной статистики и статистики партнёров. Ввод и исправление счёта в
отменённом турнире запрещены, в том числе через старые кнопки.

Меню, ввод текста и выбор игроков хранятся отдельно для каждого пользователя в
каждом чате. Просмотр статистики в личке не удаляет сообщения и не сбрасывает
действия в группе. Игроки, результаты и статистика остаются общими.

## Пинг участников беседы

- `/all` — упомянуть участников из заданного списка и известных боту участников
  текущей беседы через `@username`.
- `/all Собираемся в 19:00` — добавить этот текст в сообщение с упоминаниями.
- `/all` ответом на сообщение — отправить упоминания ответом на то же сообщение.
- `/all Собираемся в 19:00` ответом на сообщение — отправить и текст, и упоминания
  одним ответом на исходное сообщение.

В каждой беседе `/all` доступна **раз в 15 минут** для всех пользователей вместе.
При повторном вызове бот отвечает, сколько осталось ждать, без новых упоминаний.
Лимит хранится в SQLite и не сбрасывается после перезапуска. Неудачная отправка
без единого отправленного пинга не расходует лимит.

В `src/bot/allMentionUsernames.ts` добавлен исходный список из 26 участников.
Они упоминаются сразу, даже если бот ещё не видел их сообщений или не может
проверить участников через API. Повторные username исключаются без учёта регистра.
Этот ручной список нужно обновлять при выходе участников или смене их username.
Ручной список используется только в одной заданной беседе. Задайте
`ALL_MENTIONS_CHAT_ID=-5504357996` в `.env` и перезапустите бота. Без этой настройки
ручной список не используется ни в одной группе.

Участники без username упоминаются по имени со ссылкой на Telegram-профиль.
Для автоматически найденных участников боты и вышедшие участники исключаются;
присутствие и актуальные username проверяются перед отправкой. Если проверка
через API недоступна, пингуется ручной список и успешно проверенные участники.
В темах пинг остаётся в теме команды. Длинные списки
разбиваются на несколько сообщений; добавленный текст выводится один раз.

**Автоматическое пополнение списка:** сделайте бота администратором группы. Telegram Bot API не отдаёт
полный список участников: бот запоминает авторов видимых сообщений, нажатий кнопок,
участников из ответов и событий входа/выхода, а также получает администраторов.
Участникам вне ручного списка достаточно один раз написать сообщение после
обновления бота. Пока бот не увидел каждого, `/all` может охватить не всю беседу.
Список хранится отдельно для каждого чата в SQLite и сохраняется при перезапуске.
Обычные сообщения группы без активного диалога с ботом не удаляются и не вызывают меню.

Ограничения API: [участник чата](https://core.telegram.org/bots/api#getchatmember),
[события участников](https://core.telegram.org/bots/api#update),
[видимость сообщений](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Алгоритм

Для 4, 8, 12 и 16 игроков применяется one-factorization полного графа через Circle Method. В каждом из `N - 1` циклов игрок получает нового партнёра; команды объединяются в матчи backtracking-поиском с минимальным числом повторных соперников. Если кортов меньше, чем матчей цикла, матчи из разных циклов распределяются по общим раундам без одновременного участия игрока в двух матчах. Полные раунды упорядочиваются с учётом баланса игр и отдыха.

Равное число матчей у всех игроков важнее заполнения кортов. Если исходное число матчей не делится на число используемых кортов, последний раунд остаётся неполным: лишние матчи не добавляются. Для 12 игроков на 2 кортах это **16 раундов по 2 матча и один матч в 17-м раунде**: каждый играет ровно 11 матчей, все 66 пар партнёров встречаются без повторов. Уже сохранённые турниры автоматически не пересчитываются; новое расписание применяется при создании турнира.

Для **11 игроков на 2 кортах** используется короткий равный формат: **11 раундов, каждому по 8 матчей с разными партнёрами и по 3 отдыха**. Паузы равномерно распределены, отдыха два раунда подряд нет. Циклическое расписание гарантирует равное число игр; соперники подбираются с минимизацией повторов. При указании большего числа кортов используются два, поскольку для третьего матча игроков недостаточно.

Для остальных размеров с отдыхом строится короткий равный формат из `N` раундов: каждому по `4 × min(courts, floor(N / 4))` матчей. Например, для 10 игроков на 2 кортах — 10 раундов и по 8 матчей. `BalanceOptimizer` разрешает отдых только игрокам с наибольшим текущим числом игр, поэтому итоговое равенство обязательно. Среди допустимых составов `MatchScheduler` и `ScoringFunction` подбирают партнёров и соперников с минимизацией повторов детерминированным ограниченным backtracking-поиском. Если отдыха нет, достаточно `N − 1` раундов.

Максимальное число одновременно активных игроков равно `min(floor(players / 4) * 4, courts * 4)`: остаток менее четырёх неизбежно отдыхает, поскольку матч требует ровно четырёх игроков. В неполном заключительном раунде активных игроков меньше.
